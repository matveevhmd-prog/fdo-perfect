## 4. Рекомендація Claude
1. **А — корінне рішення для всього ARCHI** (бот, звіти, чат, імпорт): ліміт зникає повністю, код не переписується. Потребує плану міграції з відкатом (паралельний запуск, перемикання вебхука, повернення на Cloud у разі збою) і плану резервних копій.
2. **Для комерційної пропозиції й вкладки «Кошторис»** — Mini App з розрахунком у SQL без виконання на кожну зміну (торг «наживо» миттєвий); де саме живе API Mini App (самостійний n8n чи Supabase Edge) — вирішити після А.
3. В — лише як тимчасовий місток, якщо міграція А затягнеться.

## 5. Не перевірено
Офіційні ціни й ліміти n8n (Cloud вищих тарифів, ліцензія Community Edition для комерційного продукту для клієнтів — перевірити умови ліцензії «Sustainable Use»); розбір виконань core по вузлах (які саме дії дають 3 виконання); вартість і вибір сервера; доступність n8n-шаблонів і credential-ів після переносу; чи ОСББ переїжджає разом.
