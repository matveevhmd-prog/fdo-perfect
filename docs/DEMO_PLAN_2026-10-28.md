## 5. Методологія оцінки: «демо готове»

Мірило — **факт у даних і на екрані**, не слова бота. Очікуване називає Claude до тесту; кожне число має мітку: `live SQL`, `макет`, `розрахунок вручну`.

| Рівень | Що | Метод | Критерій |
|---|---|---|---|
| D0 Дані | Свіжість і повнота | SQL: для історій кадру `max(week_start)` = поточний понеділок; `data_updated_at` ≤ 7 днів | 100% проєктів кадру |
| D1 Історії | Є 🔴, 🟡, ⛔, ⚖️, 🟢 | SQL по `project_metrics`/знімках проти таблиці розділу 1 | ≥ 1 кожного типу |
| D2 Owner Morning Test | Вердикт | власник | ✅ |
| D3 Числа в кадрі | Кожне число раскадровки | 2 проєкти × 2 числа звіряє власник; решту — Claude SQL | розбіжностей 0 |
| D4 Заборонене | «Залишок», гроші в Weekly Render, URL/токен у кадрі | пошук у виводі, чекліст кадру | 0 |
| D5 Репетиція | Два прогони раскадровки підряд | власник | без помилок і ручних обхідних дій |
| D6 Регресія | Тести | `wr_parse_agent_output` 29/0, `check_report_form.py` 0 | без змін |

**Критерій «демо готове» — усі D0–D6 одночасно.** Не пройдено хоч одне — не знімаємо.

**Межі:** Claude не відкриває Mini App і Telegram; вигляд екрана оцінює власник за скрінами. Живий вигляд Owner View і Weekly Render на 28.10 не бачили (Потребує перевірки).
