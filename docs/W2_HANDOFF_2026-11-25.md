## 2. Аудит роботи: що підтверджено, що ні
**Підтверджено наживо:** функції Кошториса (M4–M6) у Supabase; перегляд K6sm у n8n для 10 проєктів стадій (виконання `9720`: `ok=true`, різниця з чинною версією нульова); експорт workflow без токена (grep = 0).
**НЕ підтверджено наживо (чесно):**
1. Затвердження через n8n (`Commit Mode?` → `Commit Draft` → `Commit Result`) — код і SQL перевірено окремо, ланцюг у n8n не запускався (ручний тест не передає режим commit).
2. Шлях нагляду (`-АН`) у n8n — тільки офлайн і SQL.
3. Повний ланцюг з DEMO Archi Agent у Telegram: `кошторис DEMO-06` → «✅ Затвердити».
4. `nearest_*` і `percent_execution` після затвердження новим шляхом на живих даних (у SQL змінились лише `baseline_*`, `data_updated_at`, `koshtorys_*`).
**Помилки процесу сесії (для самонавчання):** (а) Claude кілька разів вигадував правила Кошториса замість звернення до нього — виправлено мануалом, п. 46, 47 і правилом 16; (б) у репетиції M5 порядок тестів дав хибний провал (тест Н-7 змінював DEMO-02 до регресії) — код не змінювався; (в) пропущений `onError` у `Commit Draft` знайшла звірка до публікації; (г) у плані K6sm було чотири помилки (нагляд, атомарність, три колонки, ролі) — знайдено самоаудитом до коду.
