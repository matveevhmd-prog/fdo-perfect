## 1. Шаблон звіту, що вже є в коді (WR-агент, Telegram)

Жорсткий шаблон у промпті. Порядок і нумерація:

```
Рентабельність_Total: план X% / прогноз Y%
ETC_Total: план …г / факт …г / прогноз …г (сума ETC_прогноз по 4 стадіях)

1. Готовність (%)_Total: прогноз N
 1.1 Стадія МБР: 🟢 або "прогноз Y%"
  1.1.1 ETC_Стадія МБР: план / факт / прогноз        (пропускається, якщо 🟢)
  1.1.2 Дедлайн МБР: план ДАТА / прогноз ДАТА        (пропускається, якщо 🟢)
 1.2 ЕП …   1.3 П …   1.4 Р …   (те саме)
2. Акти
 2.1–2.4 Стадії МБР/ЕП/П/Р: "✅ (підписаний)" або "ДАТА / N/10"   (АВТО з Money_Log)
 2.5 Ймовірність видачі документації: N/10
3. КОМЕНТАРІ ПМ
4. ПРОБЛЕМИ   (⛔ Блокер першим пунктом, якщо є)
5. ДОПОМОГА
6. ПЛАН НА ТИЖДЕНЬ   (невиконане з минулого тижня — з міткою 🔴)
```

Без грошових сум. Пороги/кольори — з `archi_thresholds`. Дати в тексті ДД.ММ.РРРР.

Автоматично (ПМ не питається): ETC_план, ETC_факт, Дедлайн_план, статус Актів,
act_probability, перевірка ⚖️ розбіжності готовності.
Збирається від ПМ (чек-лист у промпті): готовність по 4 стадіях → ETC_прогноз по
стадіях → дедлайн (без змін / нова дата) → ймовірність документації → актуальність
Актів → блокер; + статус пунктів минулого плану.

## 2. Щотижнева таблиця для наради (Weekly Render) — специфікація (18.10.2026)

Джерело правди про вигляд і склад. Зміна — лише за запитом власника, разом із цим розділом (`CLAUDE.md` п.3).
Без грошових сум. Вузли: `Fetch All Project Metrics` + `Fetch Weekly Snapshots For Grid` → `Build Weekly Render Data`
(розкладає значення; рахує лише №2 «план» і №3, див. «Відомий борг») → `Build Weekly Render HTML`; вебхуки — TECH_SPEC §5.

**Таблиця.** Рядки — проєкти (договори `contract_type='stages'`; АН не входить); у лівій колонці ID проєкту і
«оновлено ДД.ММ.РРРР» (F-28). Колонки — тижні зі знімків (`ДД.ММ.РРРР (брифінг БОТ)`) і остання «Сьогодні». Шапка
сторінки: «N проєктів · дані оновлено ДД.ММ.РРРР» (найпізніша дата серед проєктів). Колонка тижня — 270 px, таблиця
прокручується вправо.

**Колонка тижня** (дані знімка `wr_weekly_snapshots`): `2. ETC цього тижня` (Σ ETC_прогноз по 4 стадіях, лише якщо дано всі
4, інакше «—», R-02); `7. Акт` і `8. Документація` — ймовірності `N/10`; блок «Оцінка ПМ по стадіях» (готовність
МБР/ЕП/П/Р, %); тексти у порядку **10. Проблеми, 11. Допомога, 12. План на тиждень, 13. Коментар ПМ**.

**Колонка «Сьогодні»** (дані `project_metrics`, формат `план → прогноз`):

| № | Підпис | План | Прогноз / значення | Формула |
|---|---|---|---|---|
| 1 | Рентабельність | `profitability_plan_pct` | `profitability_forecast_pct` | F-15 (від контракту) |
| 2 | ETC, год | `planned_hours − actual_hours` | `etc_forecast_total_hours` | F-23 / F-06 |
| 3 | Години до кінця / бюджет | 100% | (факт + ETC_прогноз) / план годин | F-22 (**не готовність**; >100% = перевищення) |
| 4–6 | Стадія ЕП / П / Р | 100% | `stage_data[s].readiness_forecast` | F-05 |
| 7 | Акт | — | дата найближчого акту · `N/10` | F-18 |
| 8 | Документація | — | дата найближчого дедлайну · `N/10` | F-19, F-20 |
| 9 | CPI | 1.00 | `cpi_classic_evm` | F-10 (CPI за готовністю ПМ); формат — **2 знаки після коми** (рішення власника 18.10.2026) |

**Мобільна верстка (≤700 px, 18.10.2026):** колонка проєкту 84 px, кожна колонка тижня = ширина екрана мінус колонка проєкту (одна повна колонка на свайп, `scroll-snap`); підпис показника переноситься, значення — ні. Реалізовано CSS у `Build Weekly Render HTML`, не патчем.

Стадії МБР у «Сьогодні» немає (рішення власника). «—» = даних немає (не 0 і не план).

**Відомий борг (цифр не змінює):** №2 і №3 рахує `Build Weekly Render Data` — друге місце обчислення поза SQL і
`Build MiniApp Data` (TECH_SPEC §2.1). Числа збігаються з F-23 (SQL 18.10.2026: `planned_hours` = Σ планів стадій,
`actual_hours` = Σ годин стадій у всіх 14 проєктах).

**Наслідок «відповіді нема» для розрахунків (рішення власника 10.10.2026, `RELEASE_PLAN` Розділ 16):**
`archi_recalc()` рахує прогноз ТІЛЬКИ від ПМа. Якщо ETC_прогноз не дано хоч по одній стадії з готовністю < 100% — ETC_Total, прибуток і рентабельність прогноз = NULL,
плановий залишок НЕ підставляється. Стадії з готовністю 100% → ETC авто 0. В Owner View/чаті: «🔴 Прогноз відсутній: ПМ не дав ETC по <стадії>» (завжди червоний)
і сірий останній підтверджений прогноз з датою (`forecast_confirmed_pct/week`). Те саме для проєкту без жодного звіту.
