## 1. Таблиця для наради (великий екран)

Рядок = проєкт. Колонки: **ГАП**, **ПМ**, потім по одній колонці на кожен тиждень
(дата понеділка). У клітинці "проєкт × тиждень" — один блок звіту (розділ 2).
Старіший формат (`Screenshot_1`): та сама сітка, але в клітинці лише вільний
текст коментаря ПМ. Новий формат його замінює структурованим блоком.

## 2. Блок клітинки (форма, яку заповнює Archi зі слів ПМ)

| № | Секція | Що в ній | Відповідність термінам Archi |
|---|---|---|---|
| 1 | **% ВИКОНАННЯ** | | |
| 1.1 | Фактична готовність проєкту | % по кожній стадії (на скріні: Стадія П, Стадія Р; в Archi — МБР/ЕП/П/Р) | `readiness` по стадіях з відповіді ПМ |
| 1.2 | Плановий показник на сьогодні | на скріні: % по стадіях "на сьогодні" | **НЕ переноситься.** Канон Archi: план завжди 100% (`Obraz` Розділ 4; урок 10.09). Якщо власник хоче цей рядок — це нова вимога, не канон. |

## 3. Флоу заповнення (канон, `CLAUDE.md` п.2)

1. ПМ тисне кнопку проєкту.
2. Archi показує перелік питань (по секціях 1.1, 1.4, 1.5, 2, 3, 4, 5 — розділ 4 нижче).
3. ПМ відповідає довільно: текст, фото екрану, документи.
4. "Відправити".
5. Archi структурує відповіді у форму розділу 2 і показує на екрані.
6. Archi бачить, чого бракує (порожні секції, нелогічні цифри, розбіжність ⚖️),
   ставить уточнювальні питання.
7. ПМ на кожне: чітка відповідь **або** "відповіді нема" (явний стан у звіті).
8. ПМ підтверджує → фінал → рядок у `wr_weekly_snapshots` → `archi_recalc()`.

## 4. Бріф ПМ (чернетка переліку питань, на основі форми)

Це **пропозиція**, не канон — власник коригує. Питання = секції форми:
1. Готовність по кожній стадії проєкту, %?  *(1.1)*
2. Скільки годин ще потрібно до завершення по кожній стадії? *(1.4, ETC_прогноз)*
3. Коли найближчий Акт і яка ймовірність підписання? *(1.5)*
4. Що плануєте на цей тиждень? Що з минулого плану виконано? *(2)*
5. Що нового від замовника/погоджень? *(3)*
6. Що заважає? Є блокер? *(4)*
7. Яка допомога потрібна і від кого? *(5)*

Додатково: ПМ може прикріпити скрін/документ до будь-якого питання.
