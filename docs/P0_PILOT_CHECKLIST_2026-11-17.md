```
P0-1 (C-4 + W1.8: колір лише з SQL)

   → P0-4 (окрема роль БД + RLS-політики + тест ізоляції)

   → відео (п. 35, змінено)
   → пілот Клієнта №1
```

## 4. Правила виконання кожного пункту

1. Блок «місце, вплив, борг, масштаб» (повний) перед кожною зміною n8n чи Supabase.
2. Запис `activeVersionId` до зміни; `update_workflow` через `/jsCode`; `get_workflow_version` і побайтова звірка до `publish_workflow` (п. 13).
3. Після створення вузлів — перевірити credentials (правило 11).
4. Жодного нового розкладу чи опитування (п. 14): P0 їх не потребує.
5. Після кожного пункту: `RELEASE_PLAN` (спосіб перевірки — реальний SQL/виконання), `FORMULAS`, `SECURITY.md`, `NODE_MAP`, експорт workflow з заглушкою токена, `python3 scripts/check_docs.py`.
6. Числа в звіті власнику — з позначкою джерела (live SQL / макет / розрахунок вручну).
