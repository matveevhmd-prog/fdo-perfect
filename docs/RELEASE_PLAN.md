**Знайдено і виправлено 3 реальні production-баги під час прогону** (не
точкові фікси "на бігу" — кожен зафіксований з причиною, доказом і
переліком змінених рядків):

**Bug #2 — null-поля на кроці "фінал".** JSON-схема в `WR: Build WR Prompt`
дозволяла `stage_readiness`/`etc_forecast_hours_stage`/`act_probability`/
`doc_probability` як `|null` без жодного правила, що забороняє нулити їх
на кроці "фінал", навіть якщо ПМ вже назвав ці числа раніше в розмові.
Наслідок: кожен реальний тижневий цикл писав би `NULL`-прогноз у
`project_metrics` на щойно підтвердженому фінальному кроці — Крок 8
мовчки ламався б на кожному реальному тижні. Виправлено: додано явне
правило "ці поля НІКОЛИ не null, якщо хоч раз названі за розмову", і
прибрано `|null` зі схеми для двох з чотирьох полів.

*Побічна знахідка про інструмент, не про продукт:* операція
`setNodeParameter` (JSON-pointer шлях) в MCP-тулі n8n **мовчки не
записувала** зміни в цей нод — 3 спроби поспіль (включно з тестовим
маркером-плейсхолдером) повертали "success", але жива нода лишалась
незмінною, і виконання далі падало зі старою помилкою. Перейшов на
операцію `updateNodeParameters` (повна заміна параметрів нода) — це
спрацювало одразу. Якщо в майбутньому editing великих Code-нод через цей
MCP не застосовується — перевіряти реальний вміст нода (`get_workflow_version`)
після кожного `setNodeParameter`, не довіряти самому факту "success".

**Bug #3 — LLM іноді генерує повний HTML-документ замість Telegram-тексту.**
На DEMO-03 модель один раз неправильно зрозуміла фразу промпту "сам звіт
буде окремою HTML-сторінкою" як інструкцію самій згенерувати
`<!DOCTYPE html><html>...` у полі `"message"` — Telegram відхилив це з
помилкою `Unsupported start tag "!doctype"` (execution 5603). Виправлено:
додано явну заборону повного HTML-документа в полі `message` і пояснення,
що HTML-сторінка — окремий компонент поза роллю LLM. Перетестовано на
тому самому проекті — спрацювало (execution 5605).

Перше проходження гіпотези назвало "2 місця". Це було неповно — під час
фіксу виявлено **6 окремих місць** з буквальним `demo-\d{2}` (не 2, не
5 — остаточна цифра після повного проходу й живого тесту):

2. `WR: Hard Logic Engine` — `importMatch` (`імпорт demo-NN`)
3. `WR: Hard Logic Engine` — `meetingMatch` (`зустріч demo-NN`)
4. `Doc Intake: Is Set Command?` — `^договір\s+demo-\d{2}$/i`
5. `Doc Intake: Extract Set Project` — той самий regex у Code-ноді
6. `WR: Determine Route` — **знайдено НЕ читанням коду, а живим
