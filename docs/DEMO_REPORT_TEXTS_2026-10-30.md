# Тексти звітів ПМа для живого циклу п'ятниці 30.10.2026 (сценарні)

> Створено 28.10.2026 для `docs/DEMO_PLAN_2026-10-28.md` (варіант A: живий цикл). **Це сценарні значення, а не факти про реальні проєкти.** База — знімки тижня 12.10 (live SQL 28.10.2026); прогрес за 2 пропущені тижні розраховано за правилами нижче. Власник змінює будь-яке число: звіт має бути його словами (рішення власника п. 9, варіант Б: числа, дати й блокер приймаються лише з тексту ПМа).

## Правила розрахунку (відтворювані)

| Параметр | Правило |
|---|---|
| Готовність стадії | якщо в плані минулого тижня є числова ціль (22-24 Р 86%, 24-52 П 78%, DEMO-04 Р 100%, DEMO-09 П 48%) — вона; інакше 12.10 + 2 × середній тижневий приріст за 28.09–12.10; стеля 95%, або 100%, якщо плановий дедлайн стадії ≤ 30.10; без руху (приріст 0) — лишається |
| ETC_прогноз стадії | ETC 12.10 × (1 − приріст / (100 − готовність 12.10)), округлення до 5 г, мінімум 5 г для незавершеної стадії; без руху — без змін |
| Дедлайн | збережений, якщо ≥ 02.11.2026; інакше +14 днів, але не раніше 13.11.2026 (дата незавершеної стадії не може бути в минулому — гейт «Фінал») |
| Блокер, проблеми, допомога | зі знімка 12.10 (тексти ПМа); блокер зі зазначенням типу й дати |
| Статуси плану минулого тижня | сценарні: застряглі й «проблемні» проєкти мають «не виконано» (DEMO-05, 24-11, DEMO-06, DEMO-07), «відповіді нема» — DEMO-02 |
| Документація | як 12.10 |

**Виключено:** `DEMO-03` (тестові знімки 217, 222), `24-37` (новий проєкт без історії звітів: числа довелось би вигадувати від нуля). Рішення про них — власника.

## Крок 0 (перед циклом): перенести пункти плану на тиждень 26.10

Бот шукає «план минулого тижня» за поточним понеділком (`week_start` = 2026-10-26), а пункти зі звітів 12.10 стоять на тижні 2026-10-19 (звітів 19.10 і 26.10 не було; live SQL 28.10.2026). Без переносу не буде ні «Виконання минулого плану», ні «перенесено ×N». Виконує власник у SQL Editor:

```sql
update public.wr_plan_items
set week_start = '2026-10-26'
where week_start = '2026-10-19'
  and status = 'pending'
  and project_id in ('22-24','24-11','24-52','DEMO-01','DEMO-02','DEMO-04','DEMO-05','DEMO-06','DEMO-07','DEMO-09','DEMO-10');
```

Очікую: **27 рядків** (live SQL 28.10.2026: 22-24 — 2, 24-11 — 3, 24-52 — 2, DEMO-01 — 2, DEMO-02 — 2, DEMO-04 — 3, DEMO-05 — 3, DEMO-06 — 3, DEMO-07 — 3, DEMO-09 — 1, DEMO-10 — 3). Проєкти з префіксами `ARCH-*` і `ARCH2-*` — тестове сміття, у перелік не входять. Перед запуском Claude повторно звіряє кількість SQL-ом; після — рахує рядки на `2026-10-26`.

## Крок 1 (п'ятниця 30.10): звіт по кожному проєкту

Для кожного проєкту (~3 хв [Припущення]):
1. «📝 Тижневий звіт» → вибрати проєкт → «🆕 Новий».
2. Надіслати текст з блоку нижче одним повідомленням.
3. «📤 Відправити».
4. Якщо бот питає — відповісти чітко або «відповіді нема».
5. «✅ Фінал».

Після кожного Фіналу Claude звіряє знімок у базі (скрін «Фінал прийнято» недостатній: вихід помилки вузла запису не підключений).

**Порядок:** спочатку проєкти-історії (DEMO-07, DEMO-05, 24-11, 24-52, DEMO-01, DEMO-04), далі решта.
