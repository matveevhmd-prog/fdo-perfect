# Eval-стенд чат-картки ARCHI (W15.1, `docs/PLAN_ANALYTICS_RACI_2026-11-18.md` §2)

Призначення: міряти якість відповіді моделі до і після кожної зміни промпту. Без LLM і без мережі: перевіряє вже отриману відповідь.

Запуск (з кореня репозиторію):
`node scripts/eval/run_eval.js <відповідь.json> [stop_reason] [питання] [fixture]`
Змінні: `OUT=<файл звіту>`, `SHOW=1` (показати фінальне повідомлення), `TOKENS_IN`/`TOKENS_OUT` (з `usage` виконання), `CODE_VARIANT=p2e` (версія коду вузлів у `scripts/chat_card/`).

Склад:
- `checks.js` — 19 автоперевірок C1…C16 і C20, C22, C23 (JSON, stop_reason, числа проти фактів, довжини, B-28, заборонені терміни, прийняття полів кодом).
- `fixtures/chat_data_2026-11-17.json` — вхід `Build Request Body` (демо-дані, п. 18; знімок 17.11.2026, live SQL).
- `baselines/` — відповіді моделі з виконань n8n; `reports/` — звіти прогонів.

Межі (чесно):
- Автоперевірки не міряють «глибину аналітики»; для цього — сліпа оцінка власника за рубрикою §2.3–2.4 плану.
- Фікстура — знімок 17.11. Базова відповідь 9661 отримана 18.11: «51 день» проти «50 дн.» у фікстурі дає хибний збій C4 по днях. Для чистого порівняння знімати фікстуру й відповідь в один день.
- Відповіді моделей отримує ізольований тестовий workflow n8n (ключа Anthropic у цій сесії немає) — Фаза 1б, не зроблено.
- C20 (заборонені висновки: завантаження команди, оцінні слова), C22 і C23 (верстка п. 4) — додано 19.11.2026; варіант коду `CODE_VARIANT=p2g`. C15 порівнює текст моделі незалежно від верстки (нормалізація маркерів, «;», «:», тире).
- Фікстура `chat_data_2026-11-20.json` — вхід `Build Request Body` з живого виконання 9693 (20.11.2026); база `9693_p2g_live_sonnet46.json` — сира відповідь моделі того виконання. C15 для дій — частково (≥ половини речень), бо П2h прибирає повтори тез.
